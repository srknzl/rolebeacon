VALIDATED SOURCE

What about Google, Microsoft, Amazon, Meta, Apple, Netflix, or LinkedIn?

Google Careers and Amazon Jobs have dedicated first-party connectors. LinkedIn is collected through its credential-free public job search, and optionally through a browser window you sign in to yourself when the public one is throttled too hard — either way only job searches and job postings are read, never profiles, connections, messages, or the feed. Microsoft, Meta, Apple, and Netflix still require their own adapters, so RoleBeacon reports that limitation instead of pretending the URL is supported.

LINKEDIN

Two ways to collect

Job searches and job postings only — never profiles, connections, messages, or the feed.

LinkedIn publishes no job API, so RoleBeacon reads it two ways. Both walk the same searches — one per target role, in each of your locations — and a posting collected either way deduplicates onto the same job. Pick one — running both only reads everything twice.

{% set public = linkedin_methods.get("linkedin") %} {% if public %}

Public search

no account

Reads LinkedIn's credential-free guest endpoints over plain HTTP. Nothing is signed in, no window opens, and no session is stored. This is the default, and it runs on the ordinary four-hour schedule alongside every other source.

LinkedIn throttles guest reads hard and without publishing a budget, so a walk paces itself, widens whenever it is pushed back, and takes hours over a large location. It is resumable: a run that is stopped or throttled out continues from where it stopped.

Signed-in browser

your account

Opens a visible Chrome window on a profile of its own that you sign in to yourself. RoleBeacon never sees, types, or stores a password — only Chrome keeps the session, in its own directory, and deleting that directory ends it. The job list still comes from the public search; the window is used only to read posting descriptions, which is the part the guest endpoints throttle hardest.

Automated access to signed-in LinkedIn pages is against LinkedIn's User Agreement, and the account at risk is yours — the same one you apply with. A warning, a temporary restriction, or a permanent ban are all possible outcomes. The pacing here is meant to keep a walk human-paced, not to hide it. Turn this on only if you accept that.

How a signed-in run works
  1. Turn the method on below. The searches are the same ones the public method uses.
  2. Start a refresh yourself: the Refresh now button above, or uv run rolebeacon sync --interactive --force. The background scheduler never opens a window, and the button honours each source's four-hour interval, so --force is the way to retry immediately.
  3. A Chrome window opens. If the session has expired it stops on LinkedIn's login page and waits up to five minutes for you to sign in, verification step included. It continues by itself as soon as the session exists.
  4. Leave the window open and untouched while it reads one posting at a time. Progress appears in the refresh panel and in the terminal, naming the posting being read.
  5. To stop, close the Chrome window, or press Ctrl-C if you started it from a terminal. Everything collected so far is saved and scored, and the next run resumes from that point.
